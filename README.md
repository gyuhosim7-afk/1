# 라스트 서바이버 (Last Survivor)

**▶ 바로 하기 — https://gyuhosim7-afk.github.io/1/**

이 주소를 친구에게 그대로 보내면 됩니다. 새 판을 올리면 파일 이름에 붙는
판 딱지(`?v=커밋번호`)가 바뀌므로, 친구들은 새로고침만 하면 최신판을 받아 갑니다.

친구와 함께 하려면 **구글로 로그인 → 친구 탭 → 방 만들기** 로 나온 5자리 방 코드를
알려 주세요. 같은 방에 들어온 사람끼리 한 판에서 실시간으로 만납니다
(자세한 내용은 아래 [친구와 함께 하기](#친구와-함께-하기-구글-로그인-필요)).

로비에서 모드를 고릅니다.

| 모드 | 무대 | 규칙 |
| --- | --- | --- |
| **배틀로얄** | 섬 전체 (1500m) | 참가자 30명 고정(봇 29 + 나). 파밍·자기장·수송기. 마지막까지 살아남기 |
| **1대1 결투** | 결투장 (88×64m) | 단둘이 7선승. 파밍·자기장 없음. 쓰러지면 2.4초 뒤 제자리에서 부활. 방에 친구가 있으면 그 친구와, 혼자면 봇과 |

브라우저에서 바로 돌아가는 배틀로얄 게임입니다. 두 가지 버전이 들어 있습니다.

| 2D 탑다운 | `2d/index.html` | HTML5 Canvas 기반. 위에서 내려다보는 시점 |

3D 버전이 최신이며, 2D 버전은 그대로 남겨 두었습니다.

## 3D 버전 (3d/)

### 함께 하기 (멀티플레이)

같은 링크를 연 사람들과 실시간으로 같은 섬에서 플레이합니다.
**claude.ai 아티팩트로 열었을 때만 동작합니다**(`window.claude.use('room')`).
GitHub Pages 나 파일로 직접 열면 조용히 혼자 플레이로 돌아갑니다.

- 지형·마을·아이템·자기장 계획을 씨앗 하나에서 만들어 모두가 같은 섬을 봅니다
- 위치·체력·무기는 presence 로 초당 18회 주고받고, 사격·피격·획득·사망은 이벤트로 알립니다
- 봇은 방장 한 명이 굴리고 나머지는 결과만 받아 그립니다. 방장이 나가면 자동으로 넘겨받습니다
- 총원은 사람이 늘어도 30명으로 고정입니다. 사람이 늘면 그만큼 봇을 줄입니다.
  사람 수는 방장이 보낸 참가자 목록으로 셉니다 — 각자 제 목록을 세면 목록이
  아직 안 맞은 순간에 봇 수가 달라져 서로 다른 섬이 만들어집니다
- 로비에서 닉네임을 정하고 접속한 사람 목록을 볼 수 있습니다

### 1대1 결투 (결투장)

좁은 밀폐 투기장에서 단둘이 실력만 겨루는 모드입니다.

- **맵**: 원점 기준 180° 회전 대칭입니다. 한쪽만 정의하고 부호를 뒤집어
  복사하므로 두 사람의 조건이 완전히 같습니다. 중앙 고지 하나, 좌우에
  모래색 거점 둘, 시작 지점에서 세 갈래로 갈라지는 통로로 이루어집니다.
- **장비**: 둘 다 **반달 + 권총**, 실드 50 으로 같습니다. 파밍이 없어 장비 운이
  개입하지 않습니다. 자가 치료와 투척 무기는 없습니다.
- **부활**: 쓰러지면 2.4초 뒤 제 시작 지점에서 되살아나고, 그 직후 1.2초는
  맞지 않습니다(시작 지점 앞에서 기다리는 것을 막습니다).
- **승패**: 먼저 7점을 낸 쪽이 이깁니다. 자기 실수로 죽으면 상대에게 한 점 갑니다.
- **상대**: 친구 탭에서 방을 만들어 친구가 들어온 상태로 시작하면 그 친구와 붙습니다.
  방에 아무도 없으면 봇과 붙습니다. 결투는 두 명 전용이라, 방에 셋 이상이면
  시작하지 않고 알려 줍니다.

친구와 붙을 때 점수를 맞추는 방법: 서로의 체력은 각자 자기 쪽에서 관리합니다.
쓰러진 사람이 '죽었다' 를 알리면 상대 쪽에서 한 점을 올립니다. 1대1 에서는
누가 쓰러지든 남은 사람이 한 점을 가져가므로, 자기 실수로 죽어도 양쪽 점수가
어긋나지 않습니다. 이 알림에는 번호가 붙어 있습니다 — 위치 갱신이 알림보다
먼저 도착해 '이미 죽은 상태' 로 보이는 순간에도 점수를 빠뜨리지 않기 위해서입니다.

맵의 모든 상자는 축에 나란합니다(회전 없음). 이 게임은 화면 상자와 충돌 상자의
Y 회전 방향이 서로 반대여서, 회전을 쓰면 '벽이 없는데 막히고 벽이 있는데 통과되는'
어긋남이 생기기 쉽습니다. 결투장은 회전이 필요 없으므로 그 위험을 아예 없앴습니다.

올라설 수 있는 단에는 모두 계단을 붙였습니다. 봇은 매달려 기어오르지 못하고
걸음 높이(`CFG.STEP_UP`)만 넘을 수 있어, 계단이 없으면 봇이 못 올라옵니다.

### 로비와 수집 요소

- **로비**: 위쪽 메뉴 바(플레이 · 커스터마이징 · 보상 · 전적), 해질녘 벌판에 선 전신 캐릭터,
  왼쪽 아래 매치 설정과 시작 버튼으로 구성했습니다. 시점(1인칭/3인칭)도 여기서 고릅니다
- **BP**: 매치가 끝나면 참가 60, 처치당 25, 순위 보너스(참가자 수 − 순위) × 6,
  우승 500 BP 를 받습니다
- **상자**: 보급(150) · 전투(500) · 프리미엄(1500) 세 종류. 등급별 확률과 아이템 목록,
  중복 시 환급 BP 를 상자 탭에서 표로 공개합니다
- **스킨**: 캐릭터 스킨 11종, 총기 도장 6종. 일반/고급/희귀/전설 등급이 있고
  장착하면 로비 미리보기와 게임 안 캐릭터·무기에 그대로 적용됩니다
- 보유 아이템과 BP, 전적은 브라우저에 저장됩니다

- **지형**: 값 노이즈로 만든 높이맵 섬(한 변 1500m). 언덕, 해안선, 바다,
  절차적으로 배치한 마을 17곳과 마을을 잇는 도로
- **구조물**: 외계 광산 기지입니다. 거주동(돔 하나에 캡슐 세 동을 통로로 연결),
  캡슐 줄, 화물 창고동, 착륙장, 화물 더미, 추락한 착륙선, 풍력 발전기, 채굴 시추기.
  캡슐은 속이 막혀 있어 안에 들어가지는 못하고, 동과 동 사이 골목에서 싸웁니다.
  캡슐 옆에 쌓인 화물을 딛고 지붕으로 올라갈 수 있습니다(지붕에도 아이템이 있습니다).
  모델은 KayKit Space Base Bits(CC0) 이고, 충돌 상자는 모델의 실제 크기에서 뽑습니다
- **시점**: 기본 1인칭(손에 든 총이 함께 보입니다). `V` 키나 설정에서 어깨 너머 3인칭으로
  바꿀 수 있고, 시점 회전은 목표값을 따라가는 감속 보간으로 부드럽게 처리합니다
- **사격**: 화면 중앙 조준선이 가리키는 지점으로 나가는 히트스캔 방식.
  머리를 맞히면 2.1배 피해, 이동 중에는 탄퍼짐이 커집니다
- **판정**: three.js Raycaster 대신 상자·원기둥·지형에 대한 해석식 판정을 격자로 색인해
  나무 1000그루 환경에서도 봇 30명이 가볍게 돌아갑니다
- **HUD**: 나침반, 미니맵, 전체 지도(Tab), 피격 방향 표시, 킬 로그
- **아이템**: 총기 19종(권총·기관단총·산탄총·돌격소총·지정사수총·저격총·경기관총)이
  각각 다른 실루엣의 3D 모델로 떨어집니다. 탄약은 총마다 따로 세지 않고 **구경 6종**
  (9mm · .45 · 5.56mm · 7.62mm · 12게이지 · .300)으로 묶여, 같은 구경을 쓰는 총끼리
  나눠 씁니다. 그 밖에 헬멧·방탄조끼·가방 각 3등급, 수류탄과 연막탄, 구급상자가 있습니다
- **보급 상자**: 170초 뒤 처음, 이후 220초마다 떨어집니다. AWM 처럼 보급에서만
  나오는 총과 .300 탄이 들어 있습니다
- **차량**: 픽업트럭·버기·오토바이를 타고 넓어진 맵을 이동합니다. 총알은 창문 높이에만
  맞습니다
- **지점 표시(핑)**: `Z` 로 900m 안의 지점을 찍어 지도와 화면에 표시합니다
- **캐릭터**: 뼈대가 들어 있는 glTF 모델(three.js 예제의 Soldier.glb)을 읽어 등장인물마다
  복제해 씁니다. 서기·걷기·달리기 동작을 이동 속도에 맞춰 섞고, 쓰러짐·낙하·기어오르기는
  모델 전체를 기울여 표현합니다. 총과 헬멧, 가방은 손뼈·머리뼈·등뼈에 답니다
- **연출**: 총구 화염과 순간광, 탄착 먼지, 착지 반동, 질주 시 시야각 확대,
  해와 흐르는 구름, 물결치는 바다
- **낙하 시작**: 강하선이 섬을 가로질러 날아가고, 원하는 때에 `Space` 로 뛰어내립니다.
  상공 300m 에서 자유낙하해 95m 에서 낙하산이 자동으로 펼쳐집니다. 낙하 중에는 안개가
  걷혀 섬 전체가 보이고, 방향키로 착지 지점을 고릅니다
- **무기 두 자루**: 무기 칸이 두 개라 남는 무기는 등에 메고 다니며 즉시 교체할 수 있습니다.
  봇도 교전 거리에 맞춰 무기를 바꿉니다
- **조준경(부착물)**: 레드도트(2배), 4배율, 8배율 조준경이 아이템으로 떨어집니다.
  기관단총·돌격소총·지정사수총·저격총에 달 수 있고, 4배 이상은 정조준 시 조준경
  화면으로 바뀌며 배율에 맞춰 감도가 자동 조정됩니다. 조준경 바깥도 화면이 그대로 보입니다
- **조준점**: 화면 중앙 고정 십자선(레드도트 조준경으로 정조준하면 빨간 점).
  게임 중에는 마우스 커서를 감춥니다

### 조작 (3D)

| 키 | 동작 |
| --- | --- |
| `W` `A` `S` `D` | 이동 |
| `Shift` | 질주 |
| `Space` | 점프 |
| `C` | 앉기 (탄퍼짐 감소) |
| 마우스 | 시점 |
| 좌클릭 | 사격 |
| 우클릭 | 정조준 |
| `F` / `R` / `Q` | 줍기 / 재장전 / 치료 |
| `Tab` | 전체 지도 |
| `1` `2` / 휠 / `X` | 무기 칸 교체 |
| `T` | 조준경 떼기 / 붙이기 |
| `V` | 1인칭 · 3인칭 전환 |
| `O` | 설정 (마우스 감도) |
| `Esc` | 마우스 잠금 해제 (일시 정지) |

게임 중 `O` 키(또는 Esc 일시 정지)로 여는 설정에서 **마우스 감도**, **정조준 감도**,
**Y축 반전**, **화면 끝 회전 보조**를 조절할 수 있고 값은 브라우저에 저장되어 다음에 열 때도
유지됩니다.

조작 키는 물리 키 위치(`e.code`)로 읽으므로 **한글 입력 상태에서도 WASD 가 그대로 동작**합니다. 시점은 마우스를 움직인 만큼만 돌아가며,
움직임을 멈추면 곧바로 멈춥니다.

줍기는 발밑 4.2m 안의 아이템을 집고, 조준선이 향한 아이템은 9m 까지 집을 수 있습니다.
집을 수 있는 아이템은 크게 표시되고 화면 아래에 이름이 뜹니다.

마우스 잠금을 지원하지 않는 브라우저에서는 잠금 없이 진행하며, 커서가 화면 가장자리에
닿으면 그 방향으로 일정한 속도로 계속 돌아갑니다(설정에서 끌 수 있음). 화면 가운데에서는
마우스를 멈추면 시점도 멈춥니다. 프레임이 낮으면 해상도와 그림자, 안개 거리를 한 단계 자동으로 낮춥니다.

## 2D 버전

HTML5 Canvas와 순수 자바스크립트로만 만든 탑다운 버전입니다.

## 실행 방법

**3D 판은 로컬 서버로 열어야 합니다.** 캐릭터와 기지 부품을 `.glb` 모델 파일에서
읽어 오는데, `index.html` 을 파일로 직접 열면(`file://`) 브라우저가 보안 때문에
그 읽기를 막습니다. 그러면 로비에 캐릭터가 나오지 않고 시작할 수 없습니다
(이 경우 화면에 이유가 표시됩니다).

```bash
python3 -m http.server 8080     # 저장소 최상위에서 실행
# 그다음 http://localhost:8080 으로 접속
```

2D 판(`2d/index.html`)은 모델 파일을 쓰지 않으므로 파일로 그대로 열어도 됩니다.

### 단일 파일로 배포하기

`dist/last-survivor.html`(2D) 은 CSS 와 JS 를 모두 품은 한 개짜리 파일이라, 이 파일만
전달해도 그대로 돌아갑니다.

`dist/last-survivor-3d.html`(3D) 은 코드만 품고 있습니다. three.js 는 CDN 에서 받고
모델 파일(`3d/models/`)은 옆에 그대로 있어야 하므로, **이 파일 하나만 떼어 주면
돌아가지 않습니다.** 3D 판을 남에게 줄 때는 저장소를 통째로 올리거나 위 주소를 쓰세요.

소스를 고친 뒤에는 아래 명령으로 다시 만듭니다.

```bash
python3 tools/build-single.py
```

이 명령은 `dist/last-survivor.html`(2D)과 `dist/last-survivor-3d.html`(3D)을 함께 만듭니다.
3D 단일 파일은 three.js 만 CDN 에서 불러오고 나머지는 파일 안에 들어 있습니다.

Firebase 가 맡습니다. 무료 요금제로 충분합니다.

1. [Firebase 콘솔](https://console.firebase.google.com) 에서 프로젝트를 만듭니다.
2. **Authentication → Sign-in method → Google** 을 켭니다.
3. **Authentication → Settings → 승인된 도메인** 에 `gyuhosim7-afk.github.io` 를 넣습니다.
   (이걸 빼먹으면 로그인 창이 `auth/unauthorized-domain` 으로 거절합니다)
4. **Firestore Database** 를 만들고 규칙을 아래처럼 둡니다. 남의 기록을 건드리지
   못하게 자기 문서만 읽고 쓰도록 막는 부분입니다.

   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {

       // 내 게임 기록(BP·스킨·전적·친구 목록) — 본인만
       match /players/{uid} {
         allow read, write: if request.auth != null && request.auth.uid == uid;
       }

       // 공개 프로필(이름·친구 코드·접속 시각) — 친구 코드로 찾을 수 있어야
       // 하므로 로그인한 사람은 읽을 수 있고, 쓰기는 본인만 합니다.
       match /profiles/{uid} {
         allow read: if request.auth != null;
         allow write: if request.auth != null && request.auth.uid == uid;
       }

       // 받은 초대 — 받는 사람만 읽고 지우며, 보내는 사람만 씁니다
       match /invites/{uid}/from/{other} {
         allow read, delete: if request.auth != null && request.auth.uid == uid;
         allow create, update: if request.auth != null && request.auth.uid == other;
       }

       // 함께 하기 방과 연결 신호 — 로그인한 사람끼리
       match /rooms/{code} {
         allow read, write: if request.auth != null;
       }
       match /rooms/{code}/sig/{id} {
         allow read, write: if request.auth != null;
       }
     }
   }
   ```

5. **프로젝트 설정 → 내 앱 → 웹 앱** 을 추가하면 나오는 값을
   `3d/js/firebase-config.js` 에 채웁니다.

   ```js
   const FIREBASE_CONFIG = {
     apiKey: 'AIza...',
     authDomain: '프로젝트이름.firebaseapp.com',
     projectId: '프로젝트이름',
     appId: '1:...:web:...'
   };
   ```

   이 값들은 **공개용** 입니다. 브라우저가 어차피 받아 가므로 저장소에 올려도
   됩니다. 계정을 지키는 것은 이 값이 아니라 위 3·4번(승인된 도메인, 보안 규칙)입니다.

6. 커밋하고 푸시하면 끝입니다.

처음 로그인할 때는 **덮어쓰지 않고 합칩니다** — 이 기기에서 모은 것과 계정에 있던
것 중 BP 는 큰 쪽, 보유 스킨은 합집합, 전적은 좋은 쪽을 남깁니다. 한쪽을 날려
버리면 되돌릴 방법이 없기 때문입니다.

**네이버 로그인은 아직 안 됩니다.** 네이버 아이디로 로그인 JS SDK 는 "누구인지"
까지만 알려 주고 데이터를 저장할 곳을 주지 않습니다. Firebase 에 네이버 계정을
연결하려면 토큰을 바꿔 주는 서버가 따로 필요한데, 정적 호스팅에서는 돌릴 수
없습니다. 서버를 두게 되면 그때 붙일 수 있습니다.

### 친구와 함께 하기 (구글 로그인 필요)

로그인하면 **친구 탭**에서 친구 코드로 친구를 등록하고, 초대해서 같은 판에서
함께 플레이할 수 있습니다.

통신을 두 갈래로 나눴습니다.

- **Firestore** — 친구 목록, 접속 상태, 초대, 그리고 브라우저끼리 서로를 찾게
  해 주는 연결 신호. 드물게 바뀌는 것만 다룹니다.
- **WebRTC** — 실제 위치·사격. 브라우저끼리 직접 주고받습니다.

위치까지 Firestore 로 보내면 초당 18회 × 사람 수 만큼 쓰기가 생겨 무료 한도
(하루 2만 건)가 15분이면 바닥납니다. 브라우저끼리 직접 잇는 쪽은 아무리 보내도
요금이 들지 않고 지연도 짧습니다.

쓰는 법은 두 가지입니다.

- **방 코드로**: 친구 탭 → **방 만들기** → 나온 5자리 코드를 친구에게 알려 주면,
  친구가 *코드로 참가* 칸에 넣고 **참가** 를 누릅니다.
- **친구 목록으로**: 친구 코드로 서로를 등록해 두면 친구 옆 **초대** 한 번으로
  방이 만들어지고 초대까지 갑니다. 상대는 **참가** 만 누르면 됩니다.

둘 다 **시작** 을 누르면 같은 섬에서 만납니다.

집이 서로 다른 네트워크에 있으면 드물게 연결이 안 될 수 있습니다. 공개 STUN
서버로 대부분 뚫리지만, 회사망처럼 막힌 곳에서는 중계 서버(TURN)가 필요한데
그건 유료라 넣지 않았습니다.

이 저장소는 GitHub Pages 로 공개되어 있습니다 — https://gyuhosim7-afk.github.io/1/

Settings → Pages 에서 브랜치를 골라 배포하는 방식(Deploy from a branch)이라, 브랜치에

남들 화면은 옛날 그대로이거나 새 html 에 옛 js 가 섞여 깨집니다. 딱지가 바뀌면 주소가
달라지므로 반드시 새로 받아 갑니다.

다만 `index.html` 자체는 GitHub Pages 가 10 분쯤 캐시합니다. 방금 올린 것을 바로
확인하려면 `Ctrl+Shift+R`(맥은 `Cmd+Shift+R`) 로 한 번만 강제 새로고침하세요.

## 반달과 발로란트식 계산

발로란트는 배그와 노는 방식이 다릅니다. 거리에 따른 피해 감소가 없고, 실드는
비율이 아니라 받은 만큼 먼저 깎이며, 헤드샷 한 발로 끝납니다(원탭). 반달을
넣으면서 그 감각을 그대로 옮겼습니다.

| 값 | 반달 | 비교: M416 |
| --- | --- | --- |
| 몸통 피해 | 39 (거리 무관) | 26 → 200m 에서 15.8 |
| 헤드샷 | ×4 = **156** | ×2.1 |
| 연사 속도 | 585 RPM | 660 RPM |
| 탄창 / 재장전 | 25 / 2.5초 | 30 / 2.3초 |
| 반동 | 0.034 | 0.017 |

실드 50 + 체력 100 = 150 이므로 **머리 한 발(156) 이면 끝나고, 몸통은 네 발**
(39×4 = 156)입니다. 원작과 같은 값입니다.

세 가지 장치를 새로 넣었습니다. 모두 총별 설정이라 다른 총에는 영향이 없습니다.

- `noFalloff` — 거리에 따른 피해 감소를 받지 않습니다 (반달의 특징)
- `headMul` — 총마다 헤드샷 배수를 따로 줍니다 (없으면 공용값 2.1)
- `tap` / `bloom` — **끊어 쏘기**. 서서 `tap` 초 이상 쉬고 쏜 첫 발은 조준점에
  정확히 꽂히고(탄퍼짐 0), 연사를 이을수록 `bloom` 만큼 벌어집니다.
  측정값: 첫 발 0.00°, 2발 1.23°, 4발 3.39°, 7발 6.79°.
  계속 갈기는 것보다 한 발씩 끊어 쏘는 쪽이 유리해집니다.

**실드**는 `shieldMax > 0` 인 캐릭터에게만 적용됩니다. 배틀로얄은 그대로 방탄조끼
비율 감소를 쓰므로 두 모드의 계산이 섞이지 않습니다. 반달은 배틀로얄 전리품에도
한 자리 들어가 있는데, 거기서는 헬멧 Lv3 상대로 65.5(원탭 아님), 조끼 Lv3 상대로
23.4 가 되어 다른 소총과 비슷한 자리에 앉습니다.
