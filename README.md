- 로비에서 닉네임을 정하고 접속한 사람 목록을 볼 수 있습니다

### 1대1 결투 (결투장)

좁은 밀폐 투기장에서 단둘이 실력만 겨루는 모드입니다.

- **시점**: 1인칭이 기본입니다. 시점은 모드별로 따로 기억하므로, 배틀로얄을
  3인칭으로 해 두어도 결투는 1인칭으로 열립니다(`fpvBr` / `fpvDuel`).
- **맵**: 원점 기준 180° 회전 대칭입니다. 한쪽만 정의하고 부호를 뒤집어
  복사하므로 두 사람의 조건이 완전히 같습니다. 방을 격자로 나누고 벽마다
  문을 하나씩 **어긋나게** 뚫어, 두 방을 관통해 보이지 않게 했습니다.
- **장비**: 둘 다 **반달 + 권총**, 실드 50 으로 같습니다. 파밍이 없어 장비 운이
  개입하지 않습니다. 자가 치료와 투척 무기는 없습니다.
- **미니맵**: 상대 위치를 표시하지 않습니다. 지도로 알려 주면 모서리를 하나씩
  까고 나아가는 재미가 사라지므로, 배틀로얄과 달리 직접 찾아야 합니다.
- **조준선**: 평소에는 발로란트처럼 화면 정중앙의 점 하나만 있고 벌어지지
  않습니다. 오른클릭으로 정조준하면 화면이 당겨지고 호박색 육각 브래킷이
  뜨는데, 이 브래킷은 지금 총이 얼마나 모여 있는지에 따라 벌어집니다.
  (배틀로얄은 벌어지는 십자선을 그대로 씁니다)
- **점프**: 결투장에서는 한 번만 뜁니다. 배틀로얄에는 점프를 연타해 계속 떠오르는
  버릇이 남아 있는데(아래 참고), 결투에서는 그것이 엄폐물을 무의미하게 만들어
  막았습니다.
- **판 넘김**: 한쪽이 쓰러지면 그 판이 끝납니다. 2초 뒤 **둘 다** 체력·실드·탄약을
  새로 채우고 제 시작 지점으로 돌아갑니다 — 이긴 쪽이 남은 체력으로 다음 판까지
  이어 가지 못하게. 새 판 직후 1.2초는 맞지 않습니다(시작 지점 앞에서 기다리는
  것을 막습니다).
- **승패**: 먼저 7점을 낸 쪽이 이깁니다. 자기 실수로 죽으면 상대에게 한 점 갑니다.
- **상대**: 친구 탭에서 방을 만들어 친구가 들어온 상태로 시작하면 그 친구와 붙습니다.
  방에 아무도 없으면 봇과 붙습니다. 결투는 두 명 전용이라, 방에 셋 이상이면
  시작하지 않고 알려 줍니다.

친구와 붙을 때 점수를 맞추는 방법: 서로의 체력은 각자 자기 쪽에서 관리합니다.
쓰러진 사람이 '죽었다' 를 알리면 상대 쪽에서 한 점을 올립니다. 1대1 에서는
누가 쓰러지든 남은 사람이 한 점을 가져가므로, 자기 실수로 죽어도 양쪽 점수가
어긋나지 않습니다. 이 알림에는 번호가 붙어 있습니다 — 위치 갱신이 알림보다
먼저 도착해 '이미 죽은 상태' 로 보이는 순간에도 점수를 빠뜨리지 않기 위해서입니다.

맵의 모든 상자는 축에 나란합니다(회전 없음). 이 게임은 화면 상자와 충돌 상자의
Y 회전 방향이 서로 반대여서, 회전을 쓰면 '벽이 없는데 막히고 벽이 있는데 통과되는'
어긋남이 생기기 쉽습니다. 결투장은 회전이 필요 없으므로 그 위험을 아예 없앴습니다.

### 결투장을 좁게 유지하는 방법

트인 맵에서는 긴장감이 안 삽니다. 눈으로만 보고 고치면 놓치기 쉬워서, 두 값을
숫자로 재면서 만들었습니다.

- **시야 거리** — 걸어 다닐 수 있는 자리마다 24방향으로 눈높이 광선을 쏘고,
  '넘어다볼 수 없는 것' 에 막히는 거리를 모읍니다. 낮은 엄폐물은 서면 넘어
  보이므로 시야 차단으로 세지 않습니다.
- **닿는 넓이** — 걸어 다닐 수 있는 칸을 격자로 만들고 한쪽 시작 지점에서
  너비 우선 탐색을 돌립니다. 100%가 아니면 어딘가 갇힌 자리가 있는 것입니다.

이 두 값을 보고 잡아낸 실수 둘:

- 엄폐물(3m)이 문(4m) 바로 앞에 있어 남는 폭이 몸 반지름보다 좁아져,
  통로가 아예 끊겨 있었습니다(닿는 넓이 98.4%). 엄폐물을 방 안쪽으로 옮겼습니다.
- 방 벽을 외벽까지 붙이지 않아 1m 틈이 남았고, 그 틈을 타면 맵을 가로질러
  87m 앞까지 보였습니다. 벽을 외벽에 딱 붙였습니다.

고친 뒤 값 (처음 → 지금): 시야 중앙값 9.9 → 4.7m, 상위 10% 32.5 → 13.5m,
가장 긴 시야 87.5 → 51.5m, 50m 넘게 뚫리는 자리 0%, 닿는 넓이 100%.

벽을 얇게 두면 '격자 미로' 처럼 보이고 걸어 다닐 자리가 너무 넓어집니다.
벽 두께를 6m 로 두툼하게 세워야 방이 건물이 되고 그 사이가 복도가 됩니다
(`Arena.THICK`).

봇이 이 좁은 맵을 돌아다니는지도 확인했습니다 — 180초에 743m 이동, 가장 오래
멈춘 시간 2.0초, 6m 칸 45곳 방문. 문이 4m 라도 봇이 갇히지 않습니다.

### 봇 이동 속도

봇이 사람보다 빨랐습니다. 사람에게만 걸려 있던 제약을 봇은 지키지 않았기
때문입니다 — 사람은 **앞으로 갈 때만** 질주할 수 있고 정조준 중에는 걷기의
60%, 옆걸음·뒷걸음은 걷기 속도가 상한인데, 봇은 옆으로도 뒤로도 질주했습니다.

봇에게도 같은 규칙을 씌웠습니다(`ai.js` 의 이동 상한). `CFG.BOT_SPEED` 는
그 위에 곱하는 배수인데, 어느 쪽도 유리하지 않게 **1.0**(사람과 완전히 같음)
으로 둡니다. 난이도를 낮추고 싶을 때만 이 값을 내리면 됩니다.

`moveChar` 에 실제로 넘어간 속도를 상태별로 재서 확인한 값 (m/s, 최대):

| 상태 | 전 | 후 | 같은 상황의 사람 |
| --- | --- | --- | --- |
| 교전 중 (옆걸음) | 7.8 | **4.4** | 4.4 |
| 뒷걸음 | 7.8 | **4.4** | 4.4 |
| 앞으로 돌진 | 7.8 | 6.24 | 7.8 |
| 자기장 이동 | 7.8 | 7.8 | 7.8 |

정조준 중에는 봇이 스스로 `WALK × 0.45`(1.98)까지 줄여 조준을 모으므로,
상한(2.64)에 닿지 않습니다.

`speedNow`(실제 움직인 거리)로 재면 24 m/s 같은 값이 섞여 나오는데, 이는
끼임을 푸는 `unstickNudge` 가 0.55m 를 한 번에 옮기는 것이 잡히는 것입니다.
이동 속도를 볼 때는 `moveChar` 에 넘긴 지시 속도를 봐야 합니다.

속도를 낮춘 뒤에도 좁은 결투장을 잘 돌아다니는지 확인했습니다 — 180초에
701m 이동, 가장 오래 멈춘 시간 2.3초, 6m 칸 51곳 방문.

### 조준선과 실제 탄퍼짐을 한 곳에서

조준선(과 결투장 육각 브래킷)이 벌어지는 정도와 실제 탄퍼짐을 각각 따로
계산하고 있었습니다. 끊어 쏘기(`tap`)가 들어오면서 둘이 어긋나, 화면에는
활짝 벌어져 있는데 실제로는 조준점에 정확히 꽂히는 상태가 생겼습니다.

`Game.aimSpread(ch)` 하나로 합쳐 사격과 조준선이 같은 값을 쓰게 했습니다.
합치는 과정에서 버그도 드러났습니다 — 벌어짐을 `bloom × 연사수` 로만 구해서
연사수가 0 이면 0 이 되었고, 그래서 **걸으면서 쏘는 첫 발까지 정확히
꽂혔습니다.** 발로란트는 움직이며 쏘는 것을 크게 벌리므로 그 반대여야 합니다.
기본 탄퍼짐에서 시작해 연사만큼 더하도록 고쳤습니다.

반달 기준 측정값:

| 상태 | 탄퍼짐 |
| --- | --- |
| 정조준 · 정지 · 첫 발 | **0** (원탭 가능) |
| 정조준 · 걷기 · 첫 발 | 0.057 (전에는 0 이었음) |
| 정조준 · 정지 · 연사 5발 | 0.090 |
| 정조준 · 앉기 · 연사 2발 | 0.038 |
| 비정조준 · 걷기 · 첫 발 | 0.095 |

### 봇 시야각

봇이 **등 뒤 165m 까지 다 보고 있었습니다.** 코드에는 '시야각 밖(뒤쪽)은
조금 늦게 인지' 라는 주석만 있고 실제 검사가 없었습니다. 사람은 화면에 담긴
만큼만 보므로, 이건 봇에게만 있던 이점이었습니다.

사람의 화면 각도에 맞춰 제한했습니다 — 세로 72° 를 16:9 화면으로 펴면 가로
약 105° 입니다(`CFG.BOT_FOV`). 그 각도 밖은 `CFG.BOT_HEAR`(20m) 안쪽에서만
알아챕니다. 발소리·총성으로 아는 정도인데, 사람도 소리와 피격 방향 표시로
같은 정보를 받습니다.

확인 (봇을 세워 두고 앞/뒤에 서 볼 때):

| | 10m | 30m | 60m |
| --- | --- | --- | --- |
| 정면 | 봄 | 봄 | 봄 |
| 등 뒤 | 봄 (소리) | 못 봄 | 못 봄 |

### 봇 조준

조준도 사람과 같은 조건으로 맞췄습니다. 다만 조준은 속도와 달리 '똑같이' 의
뜻이 나뉩니다.

**없앤 것 — 사람에게 없던 인공 손해**

- 정조준 탄퍼짐에 봇에게만 1.45배를 물리고 있었습니다. 같은 총을 들어도
  봇이 더 못 맞혔습니다 → 사람과 같은 값으로
- `a.skill` (0.3~0.92)로 봇마다 조준 오차·회전 속도·반응 시간을 다르게
  주던 것을 걷어냈습니다. 이제 모든 봇이 같은 값을 씁니다

**남긴 것 — 사람의 눈과 손을 흉내내는 값**

즉시 180° 돌아보는 것은 공평이 아니라 사람이 할 수 없는 일입니다. 사람이
실제로 내는 수치에 맞춰 뒀습니다.

- `BOT_TURN 7.5` rad/s — 90°를 0.21초에 돌리는 정도
- `BOT_REACT 0.22`초 — 사람 평균 반응 속도
- `BOT_AIM_Y 1.35`m — 겨누는 높이(목 부근). 머리 판정은 1.44m 위입니다.
  가슴만 노리면 머리를 노리는 사람이 일방적으로 유리하고, 머리만 노리면
  사람보다 정확해집니다

**조준점 오차는 0 이 아니라 사람만큼**

`BOT_AIM_ERR` 을 0 으로 두면 봇의 조준점이 매 발 정확히 목 한가운데에
놓입니다. 반달의 첫 발 탄퍼짐이 0 이므로, 이건 사람이 낼 수 없는 정확도가
됩니다. 15m 정지 표적에 발당 500~660발씩 쏴서 잰 값:

| 오차 | 15m 명중% | 맞힌 것 중 머리% | 35m 명중% |
| --- | --- | --- | --- |
| 0 | 99.4 | 56.9 | — |
| 0.02 | 96.0 | 37.2 | 33.7 |
| **0.03** (채택) | **85.3** | **24.6** | **26.9** |
| 0.045 | 35.8 | 29.2 | 12.2 |

`0.03` 으로 뒀습니다. 발로란트에서 실력 있는 사람의 헤드샷률이 25% 근처인
것과 맞고, 멀어지면 명중률이 20%대로 떨어지는 모양도 사람과 같습니다.

### 점프 연타로 떠오르던 것

`moveChar` 가 공중 상태(`grounded = false`)를 **떨어질 때만** 켰습니다.

```js
} else if (ch.vy < -0.2) ch.grounded = false;   // 예전
```

솟아오르는 동안은 `vy` 가 양수라 이 줄을 타지 않아 계속 '땅에 선 것' 으로
남았고, 점프 조건이 `p.grounded` 뿐이었으므로 누를 때마다 도약 속도가 새로
얹혀 끝없이 떠올랐습니다.

배틀로얄에서는 그 나름의 재미가 있어 그대로 두고, 결투장에서만 공중에 있는
동안 확실히 끄도록 했습니다.

```js
} else if (ch.vy < -0.2 || this.duel) ch.grounded = false;
```

| | 한 번 뛰기 | 연타 |
| --- | --- | --- |
| 결투장 | 0.83m | **0.83m** |

## 실행 방법

**3D 판은 로컬 서버로 열어야 합니다.** 캐릭터와 기지 부품을 `.glb` 모델 파일에서
읽어 오는데, `index.html` 을 파일로 직접 열면(`file://`) 브라우저가 보안 때문에
그 읽기를 막습니다. 그러면 로비에 캐릭터가 나오지 않고 시작할 수 없습니다
(이 경우 화면에 이유가 표시됩니다).

```bash
python3 -m http.server 8080     # 저장소 최상위에서 실행
# 그다음 http://localhost:8080 으로 접속
```

2D 판(`2d/index.html`)은 모델 파일을 쓰지 않으므로 파일로 그대로 열어도 됩니다.

### 단일 파일로 배포하기

`dist/last-survivor.html`(2D) 은 CSS 와 JS 를 모두 품은 한 개짜리 파일이라, 이 파일만
전달해도 그대로 돌아갑니다.

`dist/last-survivor-3d.html`(3D) 은 코드만 품고 있습니다. three.js 는 CDN 에서 받고
모델 파일(`3d/models/`)은 옆에 그대로 있어야 하므로, **이 파일 하나만 떼어 주면
돌아가지 않습니다.** 3D 판을 남에게 줄 때는 저장소를 통째로 올리거나 위 주소를 쓰세요.

소스를 고친 뒤에는 아래 명령으로 다시 만듭니다.

```bash
python3 tools/build-single.py
```

이 명령은 `dist/last-survivor.html`(2D)과 `dist/last-survivor-3d.html`(3D)을 함께 만듭니다.
3D 단일 파일은 three.js 만 CDN 에서 불러오고 나머지는 파일 안에 들어 있습니다.

### 구글 로그인 붙이기 (선택)

로그인하면 BP·스킨·전적이 계정에 저장되어 다른 기기에서도 이어서 할 수 있습니다.
**설정하지 않아도 게임은 그대로 돌아갑니다** — 로그인 칸이 숨겨지고 모두 게스트로
플레이합니다. 링크를 연 친구가 로그인 화면에 막히는 일은 없습니다.

GitHub Pages 는 정적 호스팅이라 서버를 돌릴 수 없으므로, 로그인과 저장은
Firebase 가 맡습니다. 무료 요금제로 충분합니다.

1. [Firebase 콘솔](https://console.firebase.google.com) 에서 프로젝트를 만듭니다.
2. **Authentication → Sign-in method → Google** 을 켭니다.
3. **Authentication → Settings → 승인된 도메인** 에 `gyuhosim7-afk.github.io` 를 넣습니다.
   (이걸 빼먹으면 로그인 창이 `auth/unauthorized-domain` 으로 거절합니다)
4. **Firestore Database** 를 만들고 규칙을 아래처럼 둡니다. 남의 기록을 건드리지
   못하게 자기 문서만 읽고 쓰도록 막는 부분입니다.

   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {

       // 내 게임 기록(BP·스킨·전적·친구 목록) — 본인만
       match /players/{uid} {
         allow read, write: if request.auth != null && request.auth.uid == uid;
       }

       // 공개 프로필(이름·친구 코드·접속 시각) — 친구 코드로 찾을 수 있어야
       // 하므로 로그인한 사람은 읽을 수 있고, 쓰기는 본인만 합니다.
       match /profiles/{uid} {
         allow read: if request.auth != null;
         allow write: if request.auth != null && request.auth.uid == uid;
       }

       // 받은 초대 — 받는 사람만 읽고 지우며, 보내는 사람만 씁니다
       match /invites/{uid}/from/{other} {
         allow read, delete: if request.auth != null && request.auth.uid == uid;
         allow create, update: if request.auth != null && request.auth.uid == other;
       }

       // 함께 하기 방과 연결 신호 — 로그인한 사람끼리
       match /rooms/{code} {
         allow read, write: if request.auth != null;
       }
       match /rooms/{code}/sig/{id} {
         allow read, write: if request.auth != null;
       }
     }
   }
   ```

5. **프로젝트 설정 → 내 앱 → 웹 앱** 을 추가하면 나오는 값을
   `3d/js/firebase-config.js` 에 채웁니다.

   ```js
   const FIREBASE_CONFIG = {
     apiKey: 'AIza...',
     authDomain: '프로젝트이름.firebaseapp.com',
     projectId: '프로젝트이름',
     appId: '1:...:web:...'
   };
   ```

   이 값들은 **공개용** 입니다. 브라우저가 어차피 받아 가므로 저장소에 올려도
   됩니다. 계정을 지키는 것은 이 값이 아니라 위 3·4번(승인된 도메인, 보안 규칙)입니다.

6. 커밋하고 푸시하면 끝입니다.

처음 로그인할 때는 **덮어쓰지 않고 합칩니다** — 이 기기에서 모은 것과 계정에 있던
것 중 BP 는 큰 쪽, 보유 스킨은 합집합, 전적은 좋은 쪽을 남깁니다. 한쪽을 날려
버리면 되돌릴 방법이 없기 때문입니다.

**네이버 로그인은 아직 안 됩니다.** 네이버 아이디로 로그인 JS SDK 는 "누구인지"
까지만 알려 주고 데이터를 저장할 곳을 주지 않습니다. Firebase 에 네이버 계정을
연결하려면 토큰을 바꿔 주는 서버가 따로 필요한데, 정적 호스팅에서는 돌릴 수
없습니다. 서버를 두게 되면 그때 붙일 수 있습니다.

### 친구와 함께 하기 (구글 로그인 필요)

로그인하면 **친구 탭**에서 친구 코드로 친구를 등록하고, 초대해서 같은 판에서
함께 플레이할 수 있습니다.

통신을 두 갈래로 나눴습니다.

- **Firestore** — 친구 목록, 접속 상태, 초대, 그리고 브라우저끼리 서로를 찾게
  해 주는 연결 신호. 드물게 바뀌는 것만 다룹니다.
- **WebRTC** — 실제 위치·사격. 브라우저끼리 직접 주고받습니다.

위치까지 Firestore 로 보내면 초당 18회 × 사람 수 만큼 쓰기가 생겨 무료 한도
(하루 2만 건)가 15분이면 바닥납니다. 브라우저끼리 직접 잇는 쪽은 아무리 보내도
요금이 들지 않고 지연도 짧습니다.

쓰는 법은 두 가지입니다.

- **방 코드로**: 친구 탭 → **방 만들기** → 나온 5자리 코드를 친구에게 알려 주면,
  친구가 *코드로 참가* 칸에 넣고 **참가** 를 누릅니다.
- **친구 목록으로**: 친구 코드로 서로를 등록해 두면 친구 옆 **초대** 한 번으로
  방이 만들어지고 초대까지 갑니다. 상대는 **참가** 만 누르면 됩니다.

둘 다 **시작** 을 누르면 같은 섬에서 만납니다.

집이 서로 다른 네트워크에 있으면 드물게 연결이 안 될 수 있습니다. 공개 STUN
서버로 대부분 뚫리지만, 회사망처럼 막힌 곳에서는 중계 서버(TURN)가 필요한데
그건 유료라 넣지 않았습니다.

### GitHub Pages

이 저장소는 GitHub Pages 로 공개되어 있습니다 — https://gyuhosim7-afk.github.io/1/

푸시하면 1~2 분 뒤 자동으로 새 판이 올라갑니다.

`tools/build-single.py` 가 첫 화면을 만들 때 css·js·모델 주소 뒤에 커밋 번호를
`?v=` 로 붙입니다. 이게 없으면 브라우저가 예전에 받아 둔 js 를 계속 써서, 새로 올려도
남들 화면은 옛날 그대로이거나 새 html 에 옛 js 가 섞여 깨집니다. 딱지가 바뀌면 주소가
달라지므로 반드시 새로 받아 갑니다.

다만 `index.html` 자체는 GitHub Pages 가 10 분쯤 캐시합니다. 방금 올린 것을 바로
확인하려면 `Ctrl+Shift+R`(맥은 `Cmd+Shift+R`) 로 한 번만 강제 새로고침하세요.

## 반달과 발로란트식 계산

발로란트는 배그와 노는 방식이 다릅니다. 거리에 따른 피해 감소가 없고, 실드는
비율이 아니라 받은 만큼 먼저 깎이며, 헤드샷 한 발로 끝납니다(원탭). 반달을
넣으면서 그 감각을 그대로 옮겼습니다.

| 값 | 반달 | 비교: M416 |
| --- | --- | --- |
| 몸통 피해 | 39 (거리 무관) | 26 → 200m 에서 15.8 |
| 헤드샷 | ×4 = **156** | ×2.1 |
| 연사 속도 | 585 RPM | 660 RPM |
| 탄창 / 재장전 | 25 / 2.5초 | 30 / 2.3초 |
| 반동 | 0.034 | 0.017 |

실드 50 + 체력 100 = 150 이므로 **머리 한 발(156) 이면 끝나고, 몸통은 네 발**
(39×4 = 156)입니다. 원작과 같은 값입니다.

세 가지 장치를 새로 넣었습니다. 모두 총별 설정이라 다른 총에는 영향이 없습니다.

- `noFalloff` — 거리에 따른 피해 감소를 받지 않습니다 (반달의 특징)
- `headMul` — 총마다 헤드샷 배수를 따로 줍니다 (없으면 공용값 2.1)
- `tap` / `bloom` — **끊어 쏘기**. 서서 `tap` 초 이상 쉬고 쏜 첫 발은 조준점에
  정확히 꽂히고(탄퍼짐 0), 연사를 이을수록 `bloom` 만큼 벌어집니다.
  측정값: 첫 발 0.00°, 2발 1.23°, 4발 3.39°, 7발 6.79°.
  계속 갈기는 것보다 한 발씩 끊어 쏘는 쪽이 유리해집니다.

**실드**는 `shieldMax > 0` 인 캐릭터에게만 적용됩니다. 배틀로얄은 그대로 방탄조끼
비율 감소를 쓰므로 두 모드의 계산이 섞이지 않습니다. 반달은 배틀로얄 전리품에도
한 자리 들어가 있는데, 거기서는 헬멧 Lv3 상대로 65.5(원탭 아님), 조끼 Lv3 상대로
23.4 가 되어 다른 소총과 비슷한 자리에 앉습니다.

## 무기 (3D 판)

총 19종입니다. 값은 `3d/js/config.js` 의 `GUNS` 에 모여 있습니다.

| 분류 | 총 | 구경 |
| --- | --- | --- |
| 권총 | P92, R45 | 9mm, .45 |
| 기관단총 | UMP45, 벡터, MP5K | .45, 9mm |
| 산탄총 | S686, S12K | 12게이지 |
| 돌격소총 | M416, SCAR-L, AKM, 그로자 | 5.56mm, 7.62mm |
| 지정사수총 | SKS, Mini14, SLR, VSS, Mk14 | 5.56mm, 7.62mm |
| 저격총 | Kar98k, AWM | 7.62mm, .300 |
| 경기관총 | M249 | 5.56mm |

- 탄약은 **구경별로 한 주머니**를 씁니다. 같은 구경이면 총을 바꿔도 탄을 나눠 씁니다
- **AWM 과 .300 탄, 그로자는 보급 상자에서만** 나옵니다
- VSS 는 소음기와 조준경이 총에 붙어 있어 조준경을 따로 달 수 없습니다
